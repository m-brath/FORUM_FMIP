# AGENTS.md — FORUM_FMIP

FMIP (FORUM Model Intercomparison Project) reference calculations: longwave
radiative-transfer benchmarks with **ARTS 2.6 (pyarts) + FluxSimulator/DISORT**,
plus sensor-response (IASI SRF) convolution to brightness temperature.

## Repository layout

- `rawdata/` — input HDF5 files (atmospheric profiles, IREMIS emissivity, IASI SRF). **Read-only, never modify.**
- `data/` — NetCDF inputs generated by `scripts/prepare_data.py` (`atmdata.nc`, `sfcdata.nc`, `surface_emissivity.nc`, `sensor_response.nc`, `satdata.nc`). Regenerate via the script; do not hand-edit.
- `results/` — NetCDF benchmark outputs (`RADIANCE/` radiance chunks, `LW/` spectral fluxes).
- `scripts/` — all Python code. Run scripts **from the `scripts/` directory** (they use relative paths like `../data` and keep the FluxSimulator LUT cache at `<cwd>/cache/<setup_name>/`).
- `scripts/cache/` — FluxSimulator LUT cache. Generated; safe to delete to force a rebuild.

The **git repository root is `scripts/`** (remote: `https://github.com/m-brath/FORUM_FMIP.git`,
branch `master`) — not the project root. Run all git commands from `scripts/`;
`rawdata/`, `data/`, and `results/` lie outside the repository and are not tracked.

This file exists twice: `AGENTS.md` at the project root (what the editor/agent
loads) and the tracked copy `scripts/AGENTS.md` inside the repository. Keep them
identical — edit the root file, then `cp ../AGENTS.md AGENTS.md` from `scripts/`
before committing.

## Scripts

| Script | Purpose |
|---|---|
| `prepare_data.py` | Convert `rawdata/*.H5` → `data/*.nc` (run first, after any rawdata change) |
| `fmip_lw_benchmark_batch.py` | LW flux benchmark, `FluxSimulator.flux_simulator_batch` → `results/LW/` |
| `fmip_radiance_batch.py` | TOA spectral-radiance benchmark, `FluxSimulator.radiance_simulator_batch` → `results/RADIANCE/` (one file per chunk) |
| `convolve_sensor_response.py` | Convolve radiance chunks with the IASI SRF, Planck-invert to brightness temperature |
| `simple_radiance.py` | Single-column clear-sky radiance prototype (pyarts3) |
| `frtmip_aux_functions.py` | Shared helpers (species formatting, profile refinement, constants) |
| `test.py` | Throwaway pyarts3 scratch script (downloads ARTS catalogs, writes `atmosphere.nc`) — not part of the benchmark |

## Conventions & gotchas

- **Run parameters are plain constants at the top of each script** (column
  subset, chunk size, `N_wvn`, angular grid, `recalc_lut`, refinement). Change
  those — there is no CLI/argument parsing.
- **One fresh `FluxSimulator` instance per chunk**: repeated batch calls on a
  single instance fail in this ARTS workspace. All instances share `setup_name`
  and therefore the same LUT cache directory.
- **LUT cache**: built up front from *all* atmospheres in the input file. If the
  spectrum or species setup changes, delete `scripts/cache/<setup_name>/` (or set
  `recalc_lut = True`) or results will be silently wrong.
- **Level ordering differs by file**: `atmdata.nc` is TOA-first, but radiance
  arrays returned by the batch calls are surface-first (index 0 = SFC, last =
  TOA). The TOA slice is `radiance[i][:, -1, :, :]`.
- Surface reflectivity is passed per column as `1 - emissivity`, interpolated
  onto the simulation wavenumber grid; DISORT derives emissivity as `1 - albedo`.
- Radiance units are raw ARTS/DISORT spectral radiance (W m⁻² Hz⁻¹ sr⁻¹).
- Code style: module docstring, `# ===` section banners with `# %%` cells,
  English comments. Keep new code consistent with the existing scripts.
