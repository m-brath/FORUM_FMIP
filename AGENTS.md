# AGENTS.md — FORUM_FMIP

FMIP (FORUM Model Intercomparison Project) reference calculations: longwave
radiative-transfer benchmarks with **ARTS 2.6 (pyarts) + FluxSimulator/DISORT**,
plus sensor-response (IASI SRF) convolution to brightness temperature.

## Repository layout

- `rawdata/` — input HDF5 files (atmospheric profiles, IREMIS emissivity, IASI SRF). **Read-only, never modify.**
- `data/` — NetCDF inputs generated by `scripts/prepare_data.py` (`atmdata.nc`, `sfcdata.nc`, `surface_emissivity.nc`, `sensor_response.nc`, `satdata.nc`). Regenerate via the script; do not hand-edit.
- `results/` — NetCDF benchmark outputs (`RADIANCE/` radiance products, `LW/`
  spectral fluxes, `LMIX_TEST/` generated line-mixing test artifacts —
  shadow catalog trees + single-column test runs, `CO2_XSEC/` single-state CO₂
  cross-section and line-wing-cutoff effect test products). Radiance runs are
  stored one folder per
  run/configuration: `results/RADIANCE/<run_name>/` with
  `run_name = <setup_name>_Nf<N_wvn>_Nza<N_za>`; the post-processing scripts
  discover files there recursively.
- `scripts/` — all Python code. Run scripts **from the `scripts/` directory** (they use relative paths like `../data` and keep the FluxSimulator LUT cache at `<cwd>/cache/<setup_name>/`).
- `scripts/cache/` — FluxSimulator LUT cache. Generated; safe to delete to force a rebuild.
- `configs/` — per-frequency-chunk JSON configs written by `fmip_radiance_slurm_main.py`, one subfolder per run (`configs/<run_name>/`). Generated; safe to delete.

The **git repository root is `scripts/`** (remote: `https://github.com/m-brath/FORUM_FMIP.git`,
branch `master`) — not the project root. Run all git commands from `scripts/`;
`rawdata/`, `data/`, and `results/` lie outside the repository and are not tracked.

This file exists twice: `AGENTS.md` at the project root (what the editor/agent
loads) and the tracked copy `scripts/AGENTS.md` inside the repository. Keep them
identical — edit the root file, then `cp ../AGENTS.md AGENTS.md` from `scripts/`
before committing.

## Scripts

| Script | Role / data flow |
|---|---|
| `prepare_data.py` | Upstream of everything: `rawdata/*.H5` → `data/*.nc`; run after any rawdata change |
| `fmip_lw_benchmark_batch.py` | Standalone LW flux benchmark → `results/LW/`; no downstream consumer |
| `fmip_radiance_batch.py` | Standalone (non-chunked) TOA radiance benchmark → `results/RADIANCE/<run_name>/`; also the module others import (`define_frequency_grid`) |
| `fmip_radiance_slurm_main.py` | Entry point for chunked radiance runs: writes JSON configs (`configs/<run_name>/`) and dispatches one job per frequency chunk to `fmip_radiance_slurm_sub.py` |
| `fmip_radiance_slurm_sub.py` | Worker for ONE frequency chunk — run ONLY via the launcher (`argv[1]` = config JSON) |
| `merge_radiance_chunks.py` | Frequency-chunk files → `Reference_radiance_TOA_merged_*.nc` in the same run folder; terminal (nothing downstream reads merged files); run constants are `run_name` and `delete_chunk_files` (opt-in removal of the chunk inputs after a successful merge) |
| `convolve_sensor_response.py` | `results/RADIANCE/<run_name>/Reference_radiance_TOA_Nf*.nc` (falls back to `Reference_radiance_TOA_merged_*.nc` if the chunk files were deleted after merging) → `Reference_convolved_*` in the same run folder; outputs are on the IASI channel grid (8461 channels, centres from `data/satdata.nc`); run constant is `run_name` |
| `convolve_sensor_response_bt.py` | Alternative diagnostic of the above: Planck-inverts the full-resolution radiance first, then applies the SRF as a weighted average in BT space → `Reference_BTconvolved_*` (float32, IASI channel grid; the optional monochromatic diagnostic keeps the sim grid on its own `frequency_sim` axis) in the same run folder; run constant is `run_name`; not picked up by `compare_convolved_with_obs.py` |
| `export_convolved_netcdf.py` | Single-file export of one run's radiance-space convolved chunks (`Reference_convolved_*`, written by `convolve_sensor_response.py`) → `Reference_convolved_<run_name>_ALL.nc` in the same run folder, with full provenance metadata (simulation frequency count/range from the chunk attrs, IASI channel grid, input vs. actual atm.-level count recomputed from `data/atmdata.nc` + `configs/<run_name>/*.json`, angular grid, species, ARTS/pyarts versions, source-file list); run constant is `run_name`; skips `_ALL.nc` on re-runs and never touches `Reference_BTconvolved_*` |
| `compare_convolved_with_obs.py` | `results/RADIANCE/<run_name>/Reference_convolved_*` + `data/satdata.nc` → stats/histograms in `results/COMPARISON/` and figures `fig_mean_bt_*` / `fig_bt_stats_*` / `fig_bt_hist_*` in `plot/comparison/`; runs after `convolve_sensor_response.py`; run constant is `run_name`, compares exactly on the shared IASI channel grid (nearest-channel collocation only for legacy sim-grid products), accumulates both the difference statistics and the mean/std of each side, and handles BT-only convolved files |
| `compare_btconvolved_with_obs.py` | Companion of `convolve_sensor_response_bt.py`: compares `Reference_BTconvolved_*` against `data/satdata.nc` by importing `compare_convolved_with_obs` (unmodified) and reusing its comparison machinery; outputs are tagged `<run_name>_BTconvolved` so the standard comparison stats/figures are never touched; run constants are `run_name` and `tag` |
| `plot_lut_species_crosssections.py` | Optional diagnostic for the T_B comparison: reads `cache/<setup>/LUT.xml` + `data/atmdata.nc`; needs `ARTS_DATA_PATH`; no downstream consumer |
| `co2_crosssection_cutoff_test.py` | Single-state CO₂ cross-section diagnostic for the 2398–2520 cm⁻¹ deficit: pure on-the-fly LBL (no FluxSimulator/`abs_lookup` on the main path) at 280 K / 1000 hPa, 2350–2550 cm⁻¹ at Δν̃ = 0.02, with `abs_lines_per_speciesCutoff` arms 25 (= benchmark 750 GHz) / 50 / 75 / 100 / 150 cm⁻¹ + untruncated → `results/CO2_XSEC/co2_xsection_280K_1000hPa_cutoffs.nc` (σ, absorption coefficient, ratio to the 25 cm⁻¹ arm, window integral, provenance) and `fig_co2_xsec_{spectra,ratios,cutoff_vs_wvn}.png` in `plot/co2_xsec/`; four self-check gates must all PASS (G1 lookup vs. on-the-fly, G2 Doppler-limit line peak, G3 σ monotonic in the cutoff, G4 half-Δν̃ resolution check); run constants at top; no downstream consumer |
| `co2_cutoff_tb_effect.py` | Radiative follow-up of `co2_crosssection_cutoff_test.py` for the 2398–2520 cm⁻¹ deficit: per-layer on-the-fly LBL absorption of column `atm_index` (again no FluxSimulator/`abs_lookup`), vertical LTE RTE → monochromatic T_B, IASI SRF convolution → sensor-level ΔT_B per cutoff arm (25/50/75/100/150 cm⁻¹ + untruncated) compared against the production sim−obs deficit read from `results/COMPARISON/comparison_stats_*.nc`, plus the log-interpolated cutoff that would close the deficit at 2405 cm⁻¹ → `results/CO2_XSEC/co2_cutoff_tb_effect_idx<N>.nc` and `fig_co2_xsec_{tb_effect,closure}_idx<N>.png` in `plot/co2_xsec/`; CO₂-**lines only** absorbers, so absolute T_B is warmer than the products (the production wing opacity is MT-CKD-continuum dominated) and only the arm differences are meaningful; gates G1–G4 (σ vs. the xsec-test products, τ→0 surface-Planck limit, τ and optically-thin T_B monotonic in the cutoff — saturated-core T_B exemptions reported, layer-grid convergence); run constants at top; no downstream consumer |
| `co2_lmix_rosenkranz_test.py` | CO2 line-mixing sensitivity test for the 2398–2520 cm⁻¹ deficit: adapts the CO2-626 bands near the simulation window via `abs_lines_per_speciesAdaptOnTheFlyLineMixing` (ECS Rodrigues1997 + MeanAir bath, `rosenkranz_adaptation` = 0 / 1, `ByRovibLinearDipoleLineMixing` — the only ECS path defined for CO2) into shadow catalog trees `results/LMIX_TEST/catdata_<variant>/` (datapath pointed at them after every `FluxSimulator` construction), then runs production-style single-column (idx 12345) TOA radiance arms `none`/`ra0`/`ra1` (optional `ra1_nocutoff`) → `results/LMIX_TEST/<setup>_Nf<Nf>_Nza20/` + figures `fig_lmix_spectra.png`/`fig_lmix_diffs.png` in `plot/lmix_test/`; run constants at top (`atm_index`, window + `N_wvn`, `lmix_variants`, adaptation order/P0/t_grid); no downstream consumer |
| `plot_lmix_report.py` | Report figures for the line-mixing test: reads the final-resolution arms `results/LMIX_TEST/co2_lmix_{none,ra0,ra1}_Nf4001_Nza20/` and adds the sensor-level view — SRF-convolved channel T_B vs. `satdata.nc` obs (operator from `frtmip_aux_functions`, only fully-covered channels), per-channel model−obs deficit, and the line-mixing shift of that deficit → `fig_report_*.png` in `plot/lmix_test/` (companion write-up: `plot/lmix_test/report_co2_line_mixing.md`); no downstream consumer |
| `frtmip_aux_functions.py` | Library, never run — shared helpers imported by `prepare_data.py`, `fmip_radiance_batch.py`, `convolve_sensor_response.py` |

## Conventions & gotchas

- **Run parameters are plain constants at the top of each script** (column
  subset, chunk size, `N_wvn`, angular grid, `recalc_lut`, refinement). Change
  those — there is no CLI/argument parsing.
- **One fresh `FluxSimulator` instance per chunk**: repeated batch calls on a
  single instance fail in this ARTS workspace. All instances share `setup_name`
  and therefore the same LUT cache directory.
- **Per-run result folders**: every radiance run writes to
  `results/RADIANCE/<run_name>/` with `run_name =
  <setup_name>_Nf<N_wvn>_Nza<N_za>` (defined as `run_name` in the batch and
  SLURM scripts; the SLURM launcher passes it to the frequency-chunk jobs so
  all chunks of one launch share one folder, and also uses it as the sub
  folder for its JSON configs, `configs/<run_name>/`). `convolve_sensor_response.py`
  and `merge_radiance_chunks.py` each have a `run_name` constant selecting the
  folder to process (convolved outputs are mirrored into that same folder);
  `compare_convolved_with_obs.py` also has a `run_name` constant and compares
  that run's convolved files against `data/satdata.nc` (collocated to the
  observation channel grid). SLURM job logs
  (*.out/*.err) are written to `results/RADIANCE/<run_name>/logs/` (the
  launcher submits `sbatch_simple` from that folder, since Slurm puts job
  logs in the submission directory; never pollute `scripts/`).
- **LUT cache**: built up front from *all* atmospheres in the input file. If the
  spectrum or species setup changes, delete `scripts/cache/<setup_name>/` (or set
  `recalc_lut = True`) or results will be silently wrong.
- **Frequency-chunked SLURM runs** (`fmip_radiance_slurm_main.py` /
  `_sub.py`): each frequency chunk gets its own FluxSimulator setup name
  `<setup_base>_<fchunk…>` and therefore its own LUT cache dir. The per-chunk
  LUT is built by the job itself, on its sub-frequency grid but from *all*
  atmospheres of the input file (like the plain benchmark) — LUT node grids
  do not depend on `f_grid`, so all chunk LUTs and the non-chunked run share
  identical state ranges and results agree with a single full-grid run.
  Changing `N_wvn` or `freq_per_chunk` changes the identifiers → new cache
  dirs. The sub-scripts pin their cwd to `scripts/` so the cache location is
  identical on levante and locally.
- **SRF convolution runs on the sensor grid**: `convolve_sensor_response.py` /
  `convolve_sensor_response_bt.py` evaluate the SRF as a unit-sum weighted
  average directly at the IASI channel centres (channel grid = `wvn` of
  `data/satdata.nc`), using the sparse weight operator from
  `frtmip_aux_functions.build_srf_channel_operator` (built once per run from
  the first input file's frequency grid) — the products therefore carry
  8461 channels instead of the simulation grid (~135 MB vs ~1.7 GB per
  variable and 2000-column chunk).  The SRF needs the full spectrum around a
  channel, so frequency-chunk files must be merged first and runs need
  `include_sensor_response = True`; channels whose SRF support is not covered
  by the input grid are dropped with a warning.
- **Figure style of the comparison plots**: axis labels use the "quantity /
  unit" notation (`T$_B$ difference / K`); the global rcParams are set once by
  `compare_convolved_with_obs.apply_plot_style()` (font `plot_font` with
  fallbacks, `palette`, `line_width`) and `annotate_spectral_features()` draws
  the atmospheric-window shading plus the dotted absorption-feature markers
  (`window_range_cm`, `spectral_features`).  `compare_btconvolved_with_obs.py`
  inherits all of it (it calls the plotting functions of
  `compare_convolved_with_obs`).
- **Level ordering differs by file**: `atmdata.nc` is TOA-first, but radiance
  arrays returned by the batch calls are surface-first (index 0 = SFC, last =
  TOA). The TOA slice is `radiance[i][:, -1, :, :]`.
- Surface reflectivity is passed per column as `1 - emissivity`, interpolated
  onto the simulation wavenumber grid; DISORT derives emissivity as `1 - albedo`.
- Radiance units are raw ARTS/DISORT spectral radiance (W m⁻² Hz⁻¹ sr⁻¹).
- Code style: module docstring, `# ===` section banners with `# %%` cells,
  English comments. Keep new code consistent with the existing scripts.
